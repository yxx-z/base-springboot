# 编码与实现规范

## 语言和注释

- 中文作为主要沟通、JavaDoc 和代码注释语言；专业名词保留标准英文。
- 注释说明原因、约束、并发语义、安全边界和失败策略，不逐行翻译代码。
- 为公共 API、复杂事务、并发控制、非直观算法和重要配置类提供完整 JavaDoc。
- 修改旧代码时保持相邻代码风格，但优先修正会误导维护者的注释。

## Java 设计

- 使用构造器注入和 `final` 依赖。
- 优先不可变对象；事件和简单值对象优先使用 record。
- 方法保持单一职责，避免大型 Controller 和万能 Service。
- 使用明确命名，例如 `resultType`、`durationMillis`，避免脱离上下文的 `type`、`time`、`data`。
- 不为不确定未来需求预留长期为空字段、接口和配置。
- 不通过复制代码规避模块边界；抽取前先确认语义真正一致。

## 异常和返回值

- 业务失败使用既有 `ApiException`、`ApiCode` 和断言工具。
- 不吞异常，不使用空 catch，不把所有异常统一改成“系统错误”。
- 辅助链路允许 best-effort 时，记录足够上下文但不能覆盖主业务原始结果。
- 异步任务必须明确线程池、失败处理、队列上限和关闭行为。
- 不用 `Thread.sleep()` 轮询异步状态；使用事件、Latch、Future、调度器或阻塞原语。

## 事务和并发

- 在 Service 层声明事务，明确回滚范围。
- 事务提交后才能执行依赖最终状态的 Session 注销、通知或外部副作用。
- 并发唯一消费、超级管理员保护、登录频控等逻辑必须有真实并发测试。
- 数据库锁的获取顺序必须稳定；MySQL REPEATABLE READ 下注意读取快照建立时机。

## 数据和隐私

- 登录账号、邮箱等在查询、缓存 Key 和持久化前统一规范化。
- 密码只保存安全摘要；比较时参数顺序为“请求明文、数据库摘要”。
- 日志、异常、审计和 URL 中禁止出现密码、验证码、Token、授权头、密钥、私钥和签名。
- 序列化请求前使用现有脱敏与长度限制能力；敏感接口直接关闭参数审计。

## 修改范围

- 保留用户工作区已有改动，不格式化或重写无关文件。
- 文件编辑使用小而完整的补丁。
- 删除或重命名后使用 `rg` 检查旧引用。
- 不使用破坏性 Git 命令恢复工作区。
